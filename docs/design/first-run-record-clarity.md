# First-run record clarity

Status: implementation, 2026-10-18. Issue #224 follows the inspection and
model-lifecycle repairs.

Installed setup must explain unavailable interaction before writing a file.
Noninteractive callers use `init --yes`; interactive prompts keep hidden key
entry and existing ceiling controls. Displayed filesystem paths are absolute
projections of the owning configuration, not new storage defaults. The quick
start leads with release installation and sends development to CONTRIBUTING.

Formation review links are generated only for artifacts that exist in that
operation directory. Absent discovery records are described as not produced,
which covers both `--no-discovery` and interrupted acquisition without inventing
a reason. No derived artifact is edited by hand.

Currentness pages distinguish the loaded study from the brief's bound study.
For a matched brief, identical recorded notes are printed once. For an old or
unbound brief, its notes stay in a separately labeled section. Checkpoint notes
describe run history; they are not a fresh test of unresolved failure. This
avoids deleting retained failures or using words in a note to decide that an
issue is resolved. Binding hashes establish identity, not semantic currentness.
The renderer version advances so regeneration preserves older views.

Verification covers noninteractive refusal before file creation, interactive
key prompts, unchanged config values with absolute displays, no-discovery
review links, exact note deduplication, old/unbound brief provenance, and
immutable regeneration. No model call, semantic verdict, or spend change is
needed for these corrections.
