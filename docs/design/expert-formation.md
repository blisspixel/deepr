# Creating an expert means developing its knowledge

Status: implemented on the development branch, unreleased, 2026-09-20.
The bounded live formation trial completed; guidance qualification remains open.

Local creation previously saved a profile and left acquisition, study, briefing,
graph materialization, and examination to separate commands. The Python example
demonstrated why this is insufficient: a name is not expertise, and a successful
study command does not establish good interpretation or advice.

The default attended local creation flow builds a research foundation at
$0 incremental external API cost. Keep an explicit profile-only path for offline
setup and automation that intentionally creates an empty profile. CLI and web
creation use the same formation service and report the same durable stages.
Existing paid and plan execution gates remain unchanged.

## Bounded formation

1. Record the mission, chosen installed local model, operation identity, limits,
   and existing artifact hashes. Resolve local capacity before model dispatch.
2. Propose topic-specific research queries using the existing acquisition arms.
   Execute a bounded free search and retain source observations, failures, and
   source hashes through the existing guarded fetch stack. Seed documents are
   evidence to retain, not evidence that has already been understood.
3. Study mechanisms, failure cases, and source scope within explicit source,
   character, model-call, and elapsed-time limits. Preserve incomplete work and
   omissions. Source acquisition is not interpretation or corroboration.
4. Form reasoned positions from the study. Preserve applicable prior positions
   and history. An invalid candidate must not replace a usable earlier brief.
5. Materialize the evidence graph and linked Markdown knowledge view from the
   actual records: concepts, mechanisms, guidance, supporting research, open
   questions, and known history. Links are copied from recorded relationships;
   code does not invent semantic equivalence, causal links, or experience.
6. Produce the dated build record and identify outstanding scope and advice
   checks. Research completion means a foundation exists. Qualification requires
   reviewed practical answers, including fresh transfer and currentness checks.

Every attempt counts toward its limits, including failed calls. Stop on capacity
failure, cancellation, or exhausted limits. No automatic provider fallback or
unbounded retry. Search silence is a failed or incomplete acquisition, not proof
that a topic has no evidence. The configured model is not changed to improve a
displayed grade. Record resource use and exact artifacts for review.

Keep a per-expert formation lock and inspect prior artifact hashes before
promotion. Concurrent changes must not be overwritten. Save completed work and
terminal failure reasons so a later attended resume can use valid evidence.
Do not present a crashed or interrupted operation as complete. Retries have new
operation identities and finite limits; they retain earlier attempts and reuse
only completed study lenses with matching model and corpus fingerprint. Source
acquisition may run again. Canonical files use individual atomic writes, not a
multi-file transaction; the consultable brief is published last. Existing bytes
and candidates are retained with the operation for inspection after interruption.

## Readable knowledge and temporal limits

The linked Markdown view is a derived projection. Each view binds its study,
brief, corpus metadata, graph, and position history by content. Regeneration
over unchanged inputs is deterministic. Keep earlier views and protect authored
files. Every position links to its findings; every finding links to the retained
source identities. Missing links, unmatched anchors, unreviewed interpretations,
unknown dates, and incomplete study remain visible.

Source observation time, source publication time, and applicability are different
properties. Do not fill unknown dates with the build date. The current evidence
graph supplies provenance, not a complete bitemporal model. Full finding revision
and validity history remains S2. This creation repair delivers the existing
knowledge foundation now and does not wait for that migration.

## Acceptance

partial fetch, invalid study/brief, call and time exhaustion, cancellation,
concurrent mutation, resume, and preservation of prior state. Inspect generated
Markdown links, graph links, hashes, unknown dates, and authored-file protection.
Verify CLI/web parity and that unavailable local capacity never constructs a
paid provider. Run a bounded real creation and practical examination at $0.
The Python record preserves unfavorable results; a successful build alone cannot
change qualification to passed.
