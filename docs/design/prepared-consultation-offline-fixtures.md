# Offline preparation fixtures during capacity qualification

2026-10-25. Narrow sequencing amendment for the authorized S1 implementation.

The existing sequence puts S1 prototypes after the final S0 protocol freeze.
Capacity development has exposed a briefing timeout and two output-truncated
studies. Those failures are retained; briefing, maintenance and answer capacity
remain unqualified. Their failure does not satisfy the original gate. The
prospective comparison, source worlds and review method exist, while final
capacity limits and held-out collection admission remain open.

The requested product outcome is preparation before advice. Waiting on every
capacity qualification before writing deterministic support fixtures would
make measurement the whole increment. Permit only offline S1 library
components and fixtures in a separate worktree while that qualification
continues: packet schemas, caller ownership, private temporary storage,
bounded acquisition controls, captured-context bindings, and mocked model and
source interactions. Use ordinary dependency injection, not a test-only
permission bypass. This is an explicit exception to the earlier sequencing,
not a claim that its prerequisite has passed.

Do not expose a preparation option through CLI, MCP or the production
transaction entrypoint before the original final-protocol gate is satisfied.
Do not perform live S1 model or source acquisition, store real caller packets,
or enable defaults through this exception. Temporary fixture directories may
exercise real platform permissions using synthetic data. Canonical expert
state remains unchanged. Existing paid-provider and persistence controls hold.

Keep evaluation recipes and their source worktrees immutable. Fixture code
belongs to the separate preparation worktree and cannot change the model,
source worlds, questions, rubric, review labels or limits of a frozen run. Do
not run local fixture tests or other competing work during a controlled local
generation trial. Remote CI may validate the separate candidate.

All implementation checks still apply: meaningful regressions, strict typing,
lint, ratchets, full unit coverage of at least 80 percent and exact-head CI.
Fixture success proves structural behavior only. It cannot qualify actual
preparation, whole-answer usefulness, S0 acceptance or improved expertise.
The original protocol gate still controls exposed or live S1 prototyping;
paired preparation-on/off review and a bounded live-source smoke still
control any later default-on decision. S2-S5 authority is unchanged.

Rejected alternatives are dropping S0 measurement, pretending missing phases
were measured, weakening coverage or source permissions, adding another
evaluator, or enabling live preparation early. Keeping all support work idle
would delay the bounded user-facing slice without protecting its live gates.
This exception may produce reviewable code, not a released capability.
